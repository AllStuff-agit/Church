# 주일 예배 PPT 만들기 (16:9)

이 스킬은 Claude가 매주 직접 실행한다. 저장소 루트는 `C:/Oddments_Repository/교회`이고, 명령은 모두 루트에서 Windows `python -X utf8`로 실행한다. 진행은 작업 목록으로 추적한다.

**16:9만 쓴다.** 4:3 자료(`9_보관/4_3/`)는 어떤 경우에도 예배 PPT에 넣지 않는다.

## 1. 입력과 날짜

기본 입력은 이 스킬 폴더의 [prompt.txt](prompt.txt)(주보·준비찬양 경로와 날짜 규칙)다. 스킬만 호출되면 이 파일을 읽고 바로 시작한다. 사용자가 경로나 날짜를 따로 주면 그것이 우선이다. `prompt.txt`는 사용자가 요청할 때만 수정한다.

- 예배 날짜: 명시된 날짜가 있으면 그것. 없으면 사용자 시간대(Asia/Seoul) 기준 **오늘 다음에 오는 일요일**, 오늘이 일요일이면 7일 뒤. 예: 2026-10-17 → `261018`, 2026-10-18 → `261025`.
- 입력의 `YYMMDD`를 모두 그 날짜로 바꿔 주보·준비찬양·결과에 같은 날짜를 쓴다.
- 입력 파일이 실제로 있는지 확인한다. 없으면 같은 폴더에서 같은 날짜의 다른 확장자(`.hwpx` 등)를 찾고, 그래도 없으면 정확한 경로를 알리고 그것만 요청한다. 다른 날짜 자료로 대신하지 않는다.
- 결과 파일이 이미 있으면 새로 만들지 수정할지 먼저 확인한다.
- 임시 폴더 `로컬전용/작업/YYMMDD/`를 만든다.

## 2. 주보 읽기

주보 이미지를 Read 도구로 직접 보고 아래를 뽑는다. 추측하지 않는다. 읽기 어려운 글자는 확대해서 다시 본다.

| 주보 항목 | 내용 json 키 | 예 |
|---|---|---|
| 예배의 부름 – 교독문 N번 | `교독문` | `49` |
| 성경봉독 | `본문` | `"사무엘하 21:1-14"` (주보의 `~`, 여러 구간 그대로 적어도 됨) |
| 설교 제목 | `설교제목` | `"공동체를 회복시키시는 하나님"` |
| 찬송(설교 전·후) | `찬송` | `[337, 300]` (구조의 번호 없는 `찬송` 순서대로) |

설교 제목 글자 배치 표기: 조사는 자동으로 작게 내려간다(이·가·도 제외). 더 작게 할 부분은 `(괄호)`, 조금 작게는 `[대괄호]`로 감싼다. 어미가 작아지는 게 어색하면 그 낱말을 `[ ]`로 감싸 자동 판단을 막는다. 주보 그대로 두고 특별한 이유가 있을 때만 표기를 넣는다.

예배 순서가 평소(`구조-주일기본.txt`)와 다르면 조립 전에 사용자에게 알리고 어떤 구조를 쓸지 확인한다.

## 3. 준비찬양 순서 읽기

준비찬양이 없다고 명시된 주는 건너뛴다.

1. HWP/HWPX를 한글 COM으로 PDF로 바꾼다: [references/hwp-pdf-reading.md](references/hwp-pdf-reading.md). PDF는 임시 폴더에 만든다.
2. `pdftoppm -r 60 -png`로 모든 쪽을 그림으로 만들어 Read 도구로 본다. 텍스트 추출로 순서를 정하지 않는다.
3. 순서: 사용자 지시가 최우선 → 번호·화살표·연결 안내 → 일반 2단 악보는 쪽마다 **왼쪽 단 위→아래, 오른쪽 단 위→아래**. 한 단에 곡이 둘이면 두 곡, 한 곡이 여러 쪽에 이어지면 한 곡이다. 빈 쪽·쪽 번호만 있는 쪽은 곡이 아니다.
4. 곡 제목은 악보에서 읽는다. 제목이 없으면 첫 가사로 웹 검색해 확인한다.
5. **진행 표시**: 곡 사이의 색 글씨·메모는 진행 지시다. `두 번째곡은 후렴으로`, `후렴으로 넘어갑니다`, `후렴부터 시작`은 이 교회에서 **그 곡의 후렴 장 → 그 곡 전체를 처음부터** 순서다. 후렴만 넣고 넘어가지 않는다. `후렴만` 등 다른 지시가 있으면 그것을 따른다.
6. 후렴 범위: 사용자 지정 → 악보의 후렴/Chorus 표시 → 선율·가사·절 구조 순으로 판단한다. 모호하면 다른 악보·음원으로 대조하고, 그래도 불확실하면 그 부분만 묻는다.

## 4. 곡 파일 찾기 (16:9만)

곡마다 순서대로:

```bash
python -X utf8 도구/worship_ppt/assemble.py search "곡 제목"
```
- `BEST_MATCH:` 경로를 쓴다. 후보가 여럿이고 애매하면 사용자에게 고르게 한다.
- 종료 코드 2(없음)이면 티스토리에서 16:9를 받는다:
  ```bash
  python -X utf8 도구/worship_ppt/assemble.py download "곡 제목"
  ```
  **곡 제목**으로 찾는다(찬송가 번호 아님). `_Wide`(16:9) 첨부만 받아 `1_자료/찬양곡/`에 저장한다.
- 그래도 없으면(종료 코드 2) 멈추고 알린다:
  > "[곡 제목]의 16:9 파일을 찾지 못했습니다. `1_자료/찬양곡/`에 넣어 주시면 이어서 진행하겠습니다."
- 준비찬양은 찬송가 번호 곡이어도 찬양곡 폴더만 쓴다.

후렴부터 시작하는 곡은 곡 파일을 그림으로 바꿔(`render`) 후렴이 몇 번째 장인지 확인한다. 후렴이 장 중간에서 시작하면 사용자에게 알린다.

## 5. 내용 정리와 조립

임시 폴더에 `내용.json`을 쓴다.

```json
{"date": "261101", "교독문": 49, "본문": "사무엘하 21:1-14",
 "설교제목": "공동체를 회복시키시는 하나님", "찬송": [337, 300],
 "준비찬양": ["1_자료/찬양곡/주여 작은 내 소망을 무릎 꿇고 아룁니다_Wide.PPT",
             {"파일": "1_자료/찬양곡/내가 늘 의지하는 예수.PPT", "후렴": [5, 6]}]}
```
- `준비찬양` 항목은 경로 문자열, 또는 후렴부터 시작하면 `{"파일": 경로, "후렴": [장 번호들(1부터)]}`. 후렴 지정 곡은 `후렴 장 → 곡 전체` 순서로 들어간다.
- 준비찬양은 곡 수만큼 섹션이 생긴다: 목록 순서대로 `준비찬양 1`, `준비찬양 2`, … 섹션 하나에 곡 하나(후렴 장 포함)가 들어간다.

조립:
```bash
python -X utf8 도구/worship_ppt/assemble.py build --구조 2_템플릿/구조/구조-주일기본.txt \
  --테마 2_템플릿/테마/테마-초록잎들꽃.pptx --내용 로컬전용/작업/YYMMDD/내용.json
```
- 조립 전 점검이 실패하면(없는 찬송·교독문·절, 후렴 장 번호 범위 등) 메시지대로 내용을 고친다.
- 끝에 섹션별 장 수와 `대조 결과`가 나온다. 종료 코드 1이면 교독문·성경 글자가 원본과 다른 것이므로 원인을 찾아 고친다.

## 6. 확인

```bash
python -X utf8 도구/worship_ppt/assemble.py render 4_예배PPT/주일/YYMMDD_주일.pptx --폴더 로컬전용/작업/YYMMDD/png
```
`sheet.png`(장 번호 표시)를 Read 도구로 본다. 장이 많으면 잘라서 본다. 확인할 것:
- 섹션 순서가 주보 순서와 같은지, 준비찬양 곡 순서와 후렴 시작이 맞는지
- 교독문: 글자 넘침, 인도/회중 구분, 마지막 `(다같이)`
- 본문표지: 본문 표기, 설교 제목 배치(따옴표 안)
- 말씀구절: 절 번호, 긴 절 나눔, 묶음 절(`18-19`)
- 찬송 번호와 주기도문송(635장)
- **준비찬양 배경**: 흰 바탕만 있는 악보 곡이 있는지 본다. 있으면 그 곡 섹션에 배경이 정상인 다른 준비찬양 섹션의 배경을 넣는다.
  - `fix-background`는 지정한 섹션의 모든 장에서 배경 이미지(악보+흰 바탕)를 흰색 투명 그림으로 옮기고, `--배경` 섹션 첫 장의 **이미지 배경**을 깐다. `--섹션`은 여러 번 줄 수 있다. 테마 슬라이드(대기 등)는 이미지 배경이 아니라서 `--배경`으로 쓸 수 없다.
  ```bash
  python -X utf8 도구/worship_ppt/assemble.py fix-background 4_예배PPT/주일/YYMMDD_주일.pptx --섹션 "준비찬양 3" --배경 "준비찬양 1"
  ```
  - 고친 뒤 `render`로 악보·가사가 상하지 않았는지 확인하고, 어느 곡을 어떤 배경으로 고쳤는지 보고한다. 정상 배경 곡이 하나도 없으면 고치지 말고 알린다.

문제가 있으면 고치고 다시 조립·확인한다. 확인하지 않은 부분을 됐다고 보고하지 않는다.

## 다른 템플릿 쓰기

절기 등으로 다른 구조·테마를 쓰면 `--구조`, `--테마`만 바꾼다. 새 테마는 9종 슬라이드(대기, 사도신경, 교독문, 참회기도, 본문표지, 말씀구절, 소식, 축도, 엔딩)를 같은 이름의 섹션에 두고, 상자 이름(`교독문번호`·`교독문부제`·`교독문제목`·`교독문본문`, `성경구절`·`설교제목` 또는 `본문 타이틀` 묶음, `구절본문`·`구절장`)을 지켜야 한다. 설계: `docs/superpowers/specs/2026-11-01-예배PPT-템플릿-구조-설계.md`.
